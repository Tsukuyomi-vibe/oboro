Основание: [chrome-region-extension-architecture.md](https://chatgpt.com/library?file_id=libfile_9e7075cf40708191b7a0ecce80e51de6&account_id=personal), версия 1 с режимом выбранных сайтов.
Статус: код I01–I22 готов, обе сборки и 214 автоматизированных тестов проходят. I21 добавляет durable-восстановление, I22 — диагностику lifecycle/документов и отрицательное покрытие workers. I23 выполнена в части ZIP-кандидатов 0.2.0 и статических проверок; реальная матрица Chrome Stable/Beta заблокирована Computer Use из-за ненадёжного определения URL. M0/M2/M3 не подтверждены. ## 1. Как выполнять план

Одна итерация — один небольшой проверяемый результат и один самостоятельный PR/коммит. В текущей папке нет Git-репозитория; результаты сохранены локально без PR/коммитов. Пользователь отдельно разрешил совместную реализацию I04–I10, затем I11–I15 и I16–I17, после них I18 и I19–I20, затем I21–I23; браузерные критерии проверяются отдельно. Для зависимого кода сохраняется проверка M0 до реальной активации. Основной ориентир — 2–4 часа сосредоточенной работы; сложные задачи выделены до 4–6 часов. Это предварительная оценка узкого объёма, а не обещание срока. После I02 и I13 оценки пересматриваются. Если объём превышает 6 часов, разделить итерацию на A/B с отдельными критериями готовности.

Итерации выполнять по зависимостям; порядок номеров подходит для последовательной работы одного разработчика. На каждом шаге сохранять устанавливаемую сборку. Незавершённый модуль держать отключённым либо явно помечать как неполный: промежуточная реализация Date не должна выдаваться за полную смену timezone.

В базовый маршрут входят I01–I30. Приёмка основной версии заканчивается на I23; работа с хранилищами — отдельное расширение I24–I30. X01–X04 необязательны и не блокируют основную версию.

## 2. Границы первой реализации

- Только Chrome Desktop и Manifest V3; IP меняется отдельным средством.
- Один активный региональный профиль для всех выбранных сайтов.
- По умолчанию selected_sites: точные хосты, опциональные поддомены, схемы HTTP/HTTPS и исключения. Пустой список ничего не включает.
- Правило API относится к адресу документа, правило Accept-Language — к адресату запроса при необходимых permissions. «Весь трафик вкладки» не является семантикой выбранного сайта.
- Внешние iframe/API добавляются отдельно; исключения важнее включений.
- Точность координат, высота, скорость и направление входят в ту же модель, что широта/долгота.
- Раскладка означает подмену Keyboard Map, а не настройку ОС и реального ввода.
- Сохранённый регион изменяется только адаптерами известных схем; серверные профили и подписанные значения не входят в универсальную подмену.
- Полная неотличимость от нативного окружения, все workers и системные диалоги не являются обещанием базовой версии.
- Разные профили на разных сайтах, правила по путям URL/портам, симуляция маршрута, другие браузеры и публикация в магазине — отдельные будущие задачи.

На момент I01 проверка состава обычной сборки пройдена: только разрешение `storage`, без host permissions, content scripts и сетевых правил. По последующему указанию пользователя выполнена реализация стенда I02; приёмка I01 от этого не считается пройденной.

## 7. Сквозные правила готовности

Перед закрытием каждой затрагивающей поведение итерации:

- [ ] Сборка и проверка типов проходят.
- [ ] Критерии именно этой итерации выполнены; не требуется заново прогонять всю матрицу без причины.
- [ ] Для изменения подмен проверены выбранный и контрольный невыбранный контексты.
- [ ] Для сетевого изменения проверен полученный сервером заголовок; для API — результат страницы, включая раннее чтение, когда оно относится к задаче.
- [ ] Не появилось скрытого расширения host permissions, allowlist или области записи.
- [ ] Выключение, отказ в разрешении и неполная поддержка не выдаются за успешное применение.
- [ ] В журнале зафиксированы версия Chrome, результат проверки, ограничения и следующий шаг.

Для простого изменения текста UI достаточно сборки и ручной проверки. Для алгоритмов времени, matcher, сетевых границ и транзакций нужны содержательные автоматизированные проверки. Проверка через привилегированный Playwright/CDP допустима как эталон, но возможности расширения подтверждаются установленным расширением.
