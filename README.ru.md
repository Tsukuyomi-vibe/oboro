# oboro

[English](README.md) | **Русский**

Расширение Chrome Manifest V3, которое применяет региональный профиль к выбранным сайтам. В одном профиле настраиваются языки браузера, геолокация, локаль форматов, часовой пояс и карта раскладки клавиатуры.

Версия: **0.0.1**. По умолчанию интерфейс английский, русский доступен в настройках. Выбор языка и темы сохраняется локально.

**Приёмка в установленном Chrome Stable/Beta ещё не завершена.** Перед применением нужен полный успешный отчёт Oboro Check для точной версии вашего Chrome. Сборка расширения и автоматические тесты сами по себе этого требования не заменяют.

## Возможности

| Настройка | На что влияет |
| --- | --- |
| Предпочитаемые языки | `navigator.language`, `navigator.languages` и заголовок запросов `Accept-Language` |
| Геолокация | Независимая подмена широты и долготы; остальные геозначения остаются исходными |
| Локаль форматов | Локаль по умолчанию для поддерживаемых конструкторов `Intl` и методов форматирования чисел, дат и строк |
| Часовой пояс | Зона по умолчанию для Date/Intl и поддерживаемого существующего Temporal.Now; локальные конструкторы, разбор, чтение и изменение дат |
| Карта раскладки | Системная карта, US QWERTY, DE QWERTZ или RU ЙЦУКЕН через доступный `Keyboard.getLayoutMap()` |
| Область действия | Явно выбранные сайты либо все сайты с выданным доступом, исключения и необязательные поддомены |
| Резервная копия | Локальный экспорт и импорт JSON с предпросмотром; поддержка старых файлов регионального профиля v1 |

Явно указанные локаль, часовой пояс и абсолютное время сохраняют своё поведение. Ввод текста, события клавиатуры, сочетания и IME остаются системными. [Полный справочник](info.md) содержит отдельные поля, API и ограничения.

## Сборка и установка

Требования:

- Node.js 22.22.2+ в ветке 22.x, 24.15.0+ в ветке 24.x либо 26+, с npm.
- Chrome 120+ как минимальная версия manifest. Доступность API и ранний запуск требуют проверки совместимости.

Из корня проекта:

```powershell
npm ci
npm run check
```

Команда проверяет типы, собирает оба расширения и запускает автоматические тесты.

1. Откройте `chrome://extensions` и включите **Режим разработчика**.
2. Нажмите **Загрузить распакованное расширение** и выберите созданную папку **dist**.
3. Откройте oboro в меню расширений и нажмите **Open settings**.
4. Разрешите пользовательские скрипты в сведениях о расширении, если Chrome показывает этот переключатель. После изменения перезагрузите расширение.
5. Пройдите проверку совместимости перед применением профиля.

При следующих обновлениях пересоберите проект, нажмите перезагрузку на существующей карточке расширения и заново откройте настройки. Сохраняйте прежний путь установки, чтобы идентификатор распакованного расширения не менялся. После обновления перезагрузите ранее обработанные страницы.

## Использование профиля

1. Введите название профиля, заполните нужные подмены и нажмите **Сохранить профиль**. **Обязательно только название.** Пустые поля используют исходные значения браузера на каждом ПК. Ноль — заданное значение координаты. Кнопка **Подставить пример «Берлин»** заполняет полный пример без сохранения.
2. Выберите **Только выбранные сайты** либо **Все сайты с уже выданным доступом** и сохраните режим. Добавьте хосты, схемы, поддомены и исключения. Пустой выбор ничего не включает; исключения имеют приоритет.
3. Пройдите [Oboro Check](docs/probe-package-readme.md). После снятия диагностической пробы и выключения диагностического расширения импортируйте полный JSON-отчёт в основное расширение.
4. Нажмите **Применить и перезагрузить выбранные страницы**. Выбранные основные страницы перезагрузятся; существующий iframe другого сайта может потребовать ручной перезагрузки родительской страницы.
5. Проверьте состояние и покрытие документов. Недостающие разрешения, неподдерживаемые API и неполные проверки показываются явно.

Выбор сайта и выдача доступа Chrome — отдельные действия. В режиме выбранных сайтов доступ сам по себе не выбирает сайт. Режим всех доступных сайтов также включает будущие выданные доступы, кроме исключений.

Несохранённые правки блокируют применение с текущей страницы настроек. После сохранения изменённого профиля требуется повторное применение. Конфликты и неподтверждённая запись сохраняют черновик и требуют перечитать сохранённое состояние.

Например, профиль `123` с одной широтой меняет только широту. Долгота и остальные геополя берутся из нативного ответа, поэтому частичной геолокации нужны разрешение браузера и успешное получение позиции. Пустое поле языков сохраняет navigator и Accept-Language; локаль, часовой пояс и карта раскладки независимы.

Для возврата исходных API выключите общий переключатель и перезагрузите ранее обработанные страницы. Выключатель снимает будущие регистрации и сетевые правила; существующие документы сохраняют обёртки до перезагрузки.

## Резервная копия конфигурации

В настройках расширения откройте **Резервная копия конфигурации** и нажмите **Экспортировать сохранённую конфигурацию**. Файл `oboro-config-<версия>.json` содержит сохранённый региональный профиль, режим выбора и правила сайтов, язык и тему интерфейса, а также подсказки доступов к сайтам. Несохранённые правки формы не включаются; экспорт сохраняет текущее состояние настроек и подмен.

Для восстановления настроек:

1. Сохраните или перечитайте несохранённые правки профиля и режима выбора сайтов, затем выберите **Файл конфигурации или старого профиля (JSON)**.
2. Проверьте **Предпросмотр импорта**: версию источника, текущие значения и значения из файла. Кнопка **Отменить импорт** оставляет сохранённые настройки без изменений.
3. Нажмите **Импортировать эти настройки**. После любого импорта подмены остаются выключенными. Перезагрузите ранее обработанные страницы, чтобы убрать прежние подмены.
4. Если появилась кнопка **Выдать недостающие доступы**, выдайте разрешения отдельно. При необходимости завершите проверку совместимости Chrome, затем явно примените восстановленный профиль.

| Файл | Что восстанавливается |
| --- | --- |
| Полная конфигурация `oboro-config`: текущий v1 и исторические v1/v2/v3 | Сохранённый профиль, режим выбора и правила сайтов, язык/тема интерфейса и подсказки доступов |
| Отдельный региональный профиль v1, v2 или v3 | Только профиль; сайты, язык/тема и подсказки доступов сохраняются. Версия приложения, создавшего файл, показывается как неизвестная. |

Импорт сохраняет текущие разрешения Chrome и не выдаёт доступы автоматически. Режим **Все сайты с уже выданным доступом** использует разрешения принимающего браузера, в том числе для адресов вне файла. Отчёты совместимости не переносятся; проверка для точной версии вашего Chrome по-прежнему обязательна.

Нумерация формата начинается заново с v1 в oboro 0.0.1; все текущие возможности сохранены. Текущий формат — `schemaVersion: 1`; каждый новый экспорт также записывает `oboroVersion` из manifest. В файл попадают только заданные подмены. При переносе профиля с одной широтой на другой ПК сохраняются исходные долгота, языки, локаль, пояс и карта клавиатуры принимающего браузера. Исторический полный v1 и файлы v2/v3 поддерживаются: удалённые настройки точности, высоты, точности высоты, скорости и направления отбрасываются с пояснением в предпросмотре. Эти пять значений всегда берутся из нативного ответа браузера. Файл более новой версии приложения с поддерживаемой схемой принимается; будущая схема или некорректные поля отклоняются до изменения настроек. При конфликте нужен повторный предпросмотр; прерванная запись использует данные отката, незавершённое восстановление блокирует дальнейшие изменения. Поддерживается JSON в UTF-8 до **1 МиБ**.

**Храните конфигурации приватно:** в них есть название профиля, заданные координаты и список сайтов. Скачанные файлы `oboro-config-*.json` исключены через [.gitignore](.gitignore). Состояние применения, локальные счётчики редакций, отчёты совместимости, идентификаторы документов и метаданные компьютера/учётки не включаются. Подробности: [контракт формата](docs/configuration-format.md) на английском и [JSON Schema v1](schemas/oboro-config.v1.schema.json), [предыдущая схема v3](schemas/oboro-config.v3.schema.json), [сохранённая схема v2](schemas/oboro-config.v2.schema.json).

## Язык интерфейса и тема

Выберите **Language → English / Русский** внизу popup либо вверху настроек и диагностики. Язык меняется сразу и сохраняется между открытиями. Открытые страницы одного расширения синхронизируют выбор без потери правок формы.

Язык интерфейса независим от языков и локали регионального профиля. У основного и диагностического расширений отдельные локальные настройки.

Для темы доступны **Как в системе**, **Светлая** и **Тёмная**. Явный выбор имеет приоритет над темой ОС и сохраняется локально.

## Совместимость и ограничения

- Расширение не меняет IP-адрес, сетевой маршрут и хранилища сайтов.
- Dedicated, Shared и Service Workers сайта не получают базовую подмену API.
- Непрозрачные или неподтверждённые about:blank/srcdoc/blob-контексты пропускаются.
- BFCache возвращает существующий документ и не применяет новую версию профиля. Для возобновления геонаблюдений или удаления прежних обёрток может понадобиться перезагрузка.
- Неоднозначные строки дат вроде `01/02/2024` возвращают `NaN` / Invalid Date. Поддерживаемые ISO-формы и явные смещения обрабатываются по документированной политике разбора.
- Отсутствующие Temporal, structuredClone и API карты клавиатуры не добавляются. Неподдерживаемая подмена времени откатывается; провал самопроверки не считается полным покрытием.
- Диагностика относится к наблюдавшимся документам. Она не доказывает отсутствие всех утечек и не делает расширение необнаружимым.

Подмена API следует области действия документа. Сетевые заголовки следуют области действия адресата запроса; Chrome также может требовать доступ к инициатору.

## Разрешения и конфиденциальность

| Разрешение | Назначение |
| --- | --- |
| `storage` | Локальные профиль, политика сайтов, применение и диагностика |
| `activeTab` | Определение текущего сайта при открытии popup |
| `userScripts` | Ранний запуск в MAIN-контексте |
| `scripting` | Изолированный диагностический bridge |
| `declarativeNetRequestWithHostAccess` | Accept-Language при выданном доступе |
| `webNavigation` | Наблюдение документов, фреймов и навигации |
| Необязательный доступ к HTTP/HTTPS-хостам | Запрос доступа к конкретному сайту по действию пользователя |

В основном расширении нет аналитики и внешнего адресата сбора данных. Профили и настройки хранятся локально. Диагностика страницы не публикует список доступов, название профиля, общий идентификатор применения и внутренние номера редакций. [Подробности конфиденциальности](docs/privacy.md).

Отчёты Oboro Check могут содержать настоящие языки, часовой пояс и версию браузера, а также время запросов. Храните эти экспорты приватно. Упаковка сохраняет только обезличенную сводку проверки и не записывает сырые консольные логи.

## Разработка

| Команда | Назначение |
| --- | --- |
| `npm run build` | Проверить типы и собрать основное расширение в dist |
| `npm run build:probe` | Проверить типы и собрать диагностическое расширение в dist-probe |
| `npm test` | Запустить тесты VM, DOM, backend и loopback HTTP |
| `npm run check` | Проверить типы, собрать оба расширения, проверить файлы/разрешения и запустить тесты |
| `npm run fixture` | Запустить локальный стенд совместимости; остановка Ctrl+C |
| `npm run package:core` | Выполнить все проверки, аудит пакетов и создать ZIP с SHA-256 |

Готовые пакеты создаются в `artifacts/release/`. Они не подписаны и не опубликованы. Версии runtime-зависимостей закреплены в package-lock.json; лицензии входят в `dist/third-party/`.

[.gitignore](.gitignore) исключает зависимости, сборки, архивы, логи, профили браузера, диагностические экспорты и локальные секреты. Профиль Берлина в examples — синтетический пример. Правила ignore не удаляют уже отслеживаемые файлы; перед публикацией проверяйте подготовленные изменения.
