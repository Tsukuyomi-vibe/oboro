# Реализация I19–I20

Историческая запись на завершение I20. Восстановление, lifecycle, актуальный набор из 214 тестов и незавершённая приёмка кандидата 0.2.0 описаны в [I21–I23](i21-i23-implementation.md).

12 ноября 2026. Код карты раскладки и редактора профиля готов. `npm run check`: TypeScript, обычная и диагностическая сборки, проверки пакетов, **187 тестов, 0 ошибок**. Лог удалён при очистке диагностических данных; [машинный статус](i19-i20-validation-status.json). Приёмка установленного Chrome и контрольные точки M0/M2 остаются открытыми. I21 не начата.

## I19 — карта раскладки

В профиле появилось поле `keyboardLayout`:

| Значение | Карта |
| --- | --- |
| native | Системная, без подмены |
| us-qwerty | Английская US QWERTY |
| de-qwertz | Немецкая DE QWERTZ |
| ru-jcuken | Русская RU ЙЦУКЕН |

Три фиксированные карты содержат по 49 writing-system keys для Windows PC, включая Space и IntlBackslash. Это набор подписей без модификаторов; dead keys представлены самостоятельными символами. Проверены основные Windows-карты [US](https://www.unicode.org/cldr/charts/41/keyboards/layouts/en.html#en-t-k0-windows), [DE](https://www.unicode.org/cldr/charts/41/keyboards/layouts/de.html#de-t-k0-windows), [RU](https://www.unicode.org/cldr/charts/41/keyboards/layouts/ru.html#ru-t-k0-windows) в Unicode CLDR 41. Mac/JIS, AltGr/Shift-слои и аппаратные варианты не входят в каталог.

SchemaVersion остаётся 1: отсутствие нового поля в прежнем профиле читается как native, без автоматической записи и увеличения revision. Неизвестные значения отвергаются. Пример «Берлин» тоже сохраняет системную карту, пока пользователь явно не выберет другую.

KeyboardRuntime устанавливается только в выбранном разрешённом документе на document_start. Нативный getLayoutMap вызывается синхронно первым. Его Promise и проверки permission policy, focus/активности документа и receiver продолжают определять успех или отказ; отказ с исходной ошибкой не превращается в карту.

После успешного нативного ответа возвращается тот же KeyboardLayoutMap: класс, prototype и идентичность кэшированного объекта сохранены. Для помеченных результатов get/has/size/entries/keys/values/forEach/Symbol.iterator читают выбранную карту. DOMString-ключ преобразуется один раз, forEach сохраняет thisArg и третий аргумент, set/delete/clear не добавляются. Непомеченные ранее созданные карты остаются нативными. Итераторы реализованы стандартными Map-итераторами; полная идентичность нативным внутренним iterator objects не заявляется. Контракт maplike описан в [Web IDL](https://webidl.spec.whatwg.org/#idl-maplike).

Карта неизменна в течение жизни документа. Trusted layoutchange от переключения системной раскладки останавливается ранним capture-обработчиком; установка не создаёт искусственного события. Обработчики страницы и её синтетические события сохраняются. Изменение профиля требует apply/reload. KeyboardEvent.key/code, обычный ввод, сочетания, lock/unlock и composition/IME не переписываются. Основание API, отказов и события — [Keyboard Map](https://wicg.github.io/keyboard-map/).

Отсутствующий, небезопасный, запрещённый или неполный API не создаётся. Состояние — native, installed, unsupported, error или not_checked; причина выводится в диагностике. installed означает установку обёрток, а не гарантию разрешения каждого последующего нативного запроса. Запрошенная фиксированная карта без installed либо несовпадающий/старый ACK не дают READY. Native не требует наличия Keyboard Map API, поскольку подмена не запрошена. Signature реализации повышена до 5, прежние документы требуют reload.

## I20 — редактор профиля

В настройках доступны название, широта/долгота, точность, высота и её точность, скорость, направление, языки, locale, timezone и карта раскладки. Поля и единицы видны в форме, обязательные значения отмечены. Допустима десятичная точка или запятая. Пустые дополнительные геополя становятся null; ноль остаётся нулём. Языки вводятся через запятые/пробелы в порядке предпочтения. Нормализация и диапазоны используют общий валидатор профиля перед отправкой сообщения backend.

Ошибка появляется у соответствующего поля и в общей области проверки; при попытке сохранения фокус переходит на первое ошибочное поле. Невалидный профиль не отправляется. Пример только заполняет форму, запись выполняется отдельной кнопкой. Прямое редактирование JSON для настроек профиля не требуется; импорт отчёта технической проверки M0 остаётся отдельным JSON-действием.

Сохранение проходит через существующий service worker и expectedRevision. Видны сохранённая версия и активная конфигурация. После изменения активного профиля старые регистрации снимаются до записи, открытым документам требуется reload; применение новой версии выполняется отдельно. Несохранённые правки блокируют apply/включение из текущей страницы настроек, сохраняя возможность выключения действующих подмен. Другие окна и popup используют последний сохранённый профиль; несохранённый черновик между окнами не распространяется.

Внешнее изменение не перезаписывает грязный черновик. Конфликт revision и неподтверждённая запись оставляют введённые значения и требуют перечитывания. Обновление, пришедшее во время save, приводит к последующему чтению сохранённой версии. Кнопка «Загрузить сохранённые значения» заменяет черновик явно. Черновик живёт в странице и не восстанавливается после её закрытия.

## Режимы сайтов

Явный переключатель с отдельным сохранением выбирает selected_sites или all_granted_sites. Оба списка правил сохраняются при переключении, исключения действуют в обоих режимах. В all_granted_sites область берётся из текущих grants; сохранённые неактивные include не требуют выдачи доступа. При возврате selected_sites снова используется include; пустой список ничего не выбирает, даже если доступ уже выдан.

Переключение режима не вызывает permissions.request. Уже выданные разрешения показаны отдельно. Конкретный доступ запрашивается только при действии с сайтом, непосредственно из пользовательского события. В режиме all_granted_sites новый выданный доступ включает адрес, если он не исключён; UI предупреждает об этом. Отказ в доступе не выдаётся за успешное включение. Удаление include не отзывает Chrome permission; адрес может остаться выбранным в all_granted_sites.

## Проверки и оставшаяся приёмка

Добавлены 24 теста: 9 KeyboardRuntime/каталога/совместимости старых профилей, 1 FrameRegistry, 14 DOM-сценариев настроек. Проверены ошибки полей, nullable/нулевые геопараметры, сохранение всех настроек, конфликт и обновление во время save, отказ доступа, пустой selected_sites, сохранность исключений и отсутствие permission request при смене режима.

DOM-тесты используют фактические HTML/JS options и bundle service worker в jsdom 31.0.0 с in-memory Chrome API. Сквозной save → apply → READY → OFF/reload использует специально синтетические M0 и native sender/lifecycle/ACK. Отдельный сценарий подтверждает, что без M0 регистрации не устанавливаются. KeyboardRuntime проверен в VM с WebIDL-подобным заменителем API. Эти тесты не доказывают доступность нативного Keyboard API, поведение системного ввода или вид страницы в установленном Chrome.

jsdom закреплён в devDependencies и lockfile, в dist/dist-probe не входит. Для проверок поддерживаются Node 22.22.2+, 24.15.0+ и 26+ соответствующих веток; фактическая среда — Node 22.23.2, ICU 78.2, tz 2026a. Production-зависимости и разрешения Chrome не добавлялись.

Первый скрипт I02 фиксирует доступность Keyboard Map API и отчёт KeyboardRuntime. Ручная кнопка запрашивает карту и показывает size/итерацию; отдельное поле позволяет проверить key/code, input и composition. История ограничена 30 событиями и остаётся в странице, в серверный отчёт текст и события ввода не включаются.

Для установленной приёмки остаются полный M0, форма и её визуальное отображение в Chrome, нативные permission policy/iframe-отказы getLayoutMap, системное layoutchange, физический ввод/сочетания/IME, выбранные и контрольные сайты и OFF/reload. M2 пока означает готовность кода основного набора, браузерная контрольная точка не закрыта. В I19/I20 новой попытки управления Chrome не было; прежнее разрешение на установку сохраняется. Установка dist/dist-probe и M0 всё ещё не завершены. [История попыток](implementation-log.md).
