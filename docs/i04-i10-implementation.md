Это запись состояния на момент I10. Следом по указанию пользователя реализован диапазон [I11–I15](i11-i15-implementation.md): watch, форматы и частичное время. Приведённые ниже ограничения и 78 тестов относятся к завершению I10.

12 ноября 2026. Пользователь явно согласовал весь диапазон I04–I10. Код диапазона реализован; I11 и последующие шаги не начинались. Полная приёмка установленного расширения остаётся открытой.

## Область сайтов и доступы

Политика хранится отдельно от профиля, по ключу `sitePolicy`. Сохранение требует актуальную `policyRevision`; эквивалентная запись не увеличивает версию. Общая очередь сериализует применение и изменения профиля/политики. Перед изменением активной конфигурации снимаются будущие собственные регистрации и правила; при ошибке очистки запись не выдаётся за успешную.

Правило задаёт хост без схемы, пути и порта, непустой список HTTP/HTTPS и includeSubdomains. Нормализуются IDNA и регистр; сравнение поддоменов учитывает границу точки. Поддомены IP запрещены. URL с завершающей точкой остаётся отдельным origin. Исключения сильнее включений. Пустой `selected_sites` не выбирает ничего; host permission сам по себе не выбирает сайт.

UI по умолчанию работает в `selected_sites`. Схема поддерживает `all_granted_sites`, но переключателя этого режима пока нет. Если такой режим сохранён, UI явно показывает его: новый выданный доступ может расширить выбор.

`permissions.request` начинается непосредственно в обработчике действия пользователя. Отказ не показывается успешным доступом: выбранное правило может сохраниться, но остаётся «нужен доступ». Исключение не запрашивает доступ. Отдельное действие выдаёт только доступ. Обязательных host permissions, статических content scripts и автоматического запроса сторонних доменов нет.

Документ и сетевой запрос оцениваются раздельно: внешний script выполняется в realm загрузившего документа; iframe — в собственном realm; fetch — по адресу получателя. Доступ к инициатору и адресату может потребоваться одновременно для DNR. Нехватка доступа отражается ограничением. Возможности API: [permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions), [match patterns](https://developer.chrome.com/docs/extensions/develop/concepts/match-patterns), [DNR](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest).

## Ранняя установка и сетевые правила

В MAIN-код заранее включены профиль, политика, выданные origins, обе revision, signature и activationId. В документе нет ожидания storage или сообщения фонового процесса перед установкой. Проверка URL выполняется синхронно. Если readyState уже не `loading`, код не устанавливает обёртки и требует reload.

Одинаковая версия не наслаивает обёртки; другая версия в существующем документе требует навигации. Нативный getter проверяет receiver; флаги дескрипторов сохранены. В список языков нельзя записать изменение профиля через возвращённый массив.

Регистрируется только собственный userScript `regional-main-v1`, isolated bridge `regional-bridge-v1` и DNR-диапазон 1800000–1800799. Чужие регистрации/правила сохраняются при применении, очистке и откате. DNR использует set Accept-Language с priority 10 и адресные исключения allow с priority 100; исключения пересекаются с выбранными scopes и не становятся глобальным allowAllRequests. Установка выполняется до reload; пустой выбор даёт пустой набор. Основные механизмы: [userScripts](https://developer.chrome.com/docs/extensions/reference/api/userScripts), [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting).

## Применение и диагностика

Порядок: validate → проверка M0 и доступных API → prepare/pending → register/rules → reload → verify → commit. Статусы: OFF, PREPARING, READY, LIMITED, ERROR, NEEDS_RELOAD, OUT_OF_SCOPE. Неполный ACK, несовпавшая revision или ошибка проверки не дают READY.

M0 не принимается по одному полю `status: CONFIRMED`. Импорт заново проверяет полный I02 JSON: исходные данные, baseline/armed/off, одну точную версию текущего Chrome, наблюдения переключателя Allow User Scripts для одного diagnostic extension и успешную очистку. Затем обычное расширение отдельно проверяет собственные API. Источник импортируемого файла подтверждает пользователь; криптографической аттестации отчёта нет. Синтетический helper тестов не является доказательством Chrome.

Координатор сохраняет pending/committed версии. При ошибке возвращает предыдущую собственную конфигурацию; уже изменённым документам нужен reload. OFF снимает будущие подмены и требует reload обработанных документов. Ошибка очистки остаётся ERROR. Новая установка выключена; сохранение профиля или выдача permission сами не запускают подмены.

Выбранные верхние страницы перезагружаются автоматически при применении. Выбранный iframe внутри невыбранной страницы требует явной перезагрузки родительской вкладки. Verify ждёт сообщения и завершение навигации до 2500 мс; позднее наблюдение может завершить проверку. При обычном перезапуске worker проверяются сохранённые версии, proof, доступы и реальные регистрации; существующий bridge повторно сообщает диагностику без поздней инъекции. Незавершённое pending после прерывания очищается и получает ERROR; полноценное восстановление относится к I21.

FrameRegistry хранит tabId/frameId/documentId/origin и revision в storage.session. URL-путь не сохраняется. Identity берётся из Chrome sender, а не payload страницы. Наблюдение MAIN помечено `telemetryTrusted: false`: оно диагностическое и не даёт странице привилегированных команд. Команды изменения принимаются только от собственных popup/options. Непокрытые about:blank/srcdoc/blob и workers не получают обещание поддержки. Основа lifecycle: [webNavigation](https://developer.chrome.com/docs/extensions/reference/api/webNavigation).

## Однократная геолокация

Подменяется только существующий `getCurrentPosition` в secure context. Сохраняются проверки receiver и callbacks, асинхронный вызов, Permission Policy и granted/denied/prompt.

При granted формируется новая синтетическая позиция. Denied даёт ошибку permission denied. При prompt штатный вызов нужен для решения Chrome; его success не читает реальные coords и передаёт синтетическую позицию. Ошибка получения permission state не включает обходной доступ к нативным координатам. Отзыв разрешения перед callback не допускает успешную выдачу.

Позиция и coords readonly, включают latitude, longitude, accuracy, altitude, altitudeAccuracy, speed, heading и toJSON. При speed 0 heading становится null. Timestamp — текущий Unix timestamp без сдвига часового пояса. Поддержаны timeout 0 и нормализация опций однократного запроса; ожидание permission не входит в timeout. Основа контракта: [W3C Geolocation](https://www.w3.org/TR/geolocation/).

**watchPosition/clearWatch остаются нативными до I11**, включая возможную выдачу реальных координат. Форматы, часовой пояс, раскладка и IP ещё не меняются. Полная неотличимость от нативной геолокации не заявляется.

## Выполненные проверки

`npm run check`: строгая типизация, обычная/диагностическая сборки, проверка manifest/HTML и **78 тестов, 0 ошибок**. Включены 9 проверок сайтов, 8 runtime/DNR, 15 координатора/реестра/backend и 8 однократной геолокации; остальные — профиль, I02 и HTTP-стенд. Chrome API проверяются тестовыми объектами; JavaScript страниц выполняется в Node VM. HTTP-стенд тестируется реальными локальными запросами.

Стенд дополнен внешним classic script, разрешёнными фиксированными редиректами и отдельным журналом resources. Первый снимок теперь содержит метаданные runtime. Запрос геолокации возможен только отдельной кнопкой; координаты отображаются локально и не отправляются в серверный отчёт. iframe делегирует geolocation через allow, что не заменяет согласие Chrome.

В реальном Chrome было получено частичное наблюдение локального стенда. Сырой отчёт и сведения браузера удалены 23 ноября при очистке диагностических данных. Отсутствие всех ранее установленных расширений отдельно не проверялось; полное покрытие стенда не было получено. Это наблюдение не подтверждало полный baseline без расширения или M0.

Дальнейшее управление Chrome остановлено самим Computer Use: инструмент не смог надёжно определить текущий URL для применения своих правил. Новые попытки браузерного управления не выполнялись. Установка обычной/диагностической сборок, Allow User Scripts, настоящая ранняя инъекция, DNR, permission dialog и visual QA новых интерфейсов не подтверждены.

## Оставшаяся ручная приёмка

1. Выполнить полный [I02](i02-test-stand.md) в чистом профиле Chrome, включая все четыре верхних хоста и iframe, on/off переключателя, первый запрос, fetch и очистку. Закрыть M0.
2. Загрузить обычную dist; проверить ошибки manifest/worker, исходный OFF, отсутствие автоматически созданного профиля и доступов.
3. Выбрать пример и selected.localhost с HTTP/поддоменами, исключить excluded.selected.localhost. Проверить отказ и выдачу permission, повторное открытие UI и реальный перезапуск Chrome.
4. Импортировать полный proof для текущей версии. Применить: первый inline и внешний script выбранного документа видят языки профиля; контрольный и исключённый документы сохраняют исходные. Проверить выбранный iframe на контрольном родителе.
5. По серверному журналу проверить первый main_frame, fetch и редиректы selected↔control; отдельно — недостаточный доступ к инициатору. Контрольный адресат сохраняет исходный заголовок.
6. В secure context вручную проверить granted, denied, prompt, все геополя, timestamp и отсутствие синхронного callback. У контрольного документа остаётся нативная геолокация.
7. Изменить profileRevision/policyRevision, удалить сайт, отозвать доступ и прервать применение: убедиться, что нет ложного READY. Выполнить OFF и reload, проверить восстановление первых чтений и заголовков.

До этих проверок I05–I10 имеют статус «код готов, приёмка Chrome не подтверждена». Дальнейшая реализация I11 требует нового указания пользователя.
