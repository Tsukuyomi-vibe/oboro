Запись отражает состояние на завершение I18. Карта раскладки и редактор описаны в [I19–I20](i19-i20-implementation.md), восстановление и актуальный набор из 214 проверок — в [I21–I23](i21-i23-implementation.md). Результаты исходной итерации ниже сохранены; native-приёмка I23 открыта.

12 ноября 2026. Код шага 18 готов. `npm run check` прошёл: TypeScript, обычная и диагностическая сборки, проверки пакетов и **163 теста, 0 ошибок**. Лог удалён при очистке диагностических данных; [машинный статус](i18-validation-status.json). Приёмка установленного Chrome и M0 остаются открытыми. I19 не начата.

## Поддерживаемые поверхности

| API | Поведение |
| --- | --- |
| Date и Intl из I12–I17 | Локальные чтение, создание, ISO-парсинг, setters и форматирование согласованы с CalendarEngine профиля |
| Temporal.Now.timeZoneId | Возвращает канонический IANA-пояс профиля |
| Temporal.Now.zonedDateTimeISO | При отсутствующей/undefined зоне использует профиль |
| Temporal.Now.plainDateTimeISO, plainDateISO, plainTimeISO | При отсутствующей/undefined зоне используют профиль |
| Существующие Now.zonedDateTime/plainDateTime/plainDate/plainTime | Поддерживаются только если уже присутствуют, с сохранением позиции календарного аргумента |
| Temporal.Now.instant | Сохранён исходный метод; точность epochNanoseconds не уменьшается до Date milliseconds |
| Явные зоны и календари | Передаются исходному методу; UTC, именованная зона, offset и допустимые объекты не заменяются |
| Date.now, Date.UTC, UTC-методы, timestamp, ISO/JSON и performance.now | Сохранены исходные абсолютные API |

Методы Now обёрнуты Proxy с сохранением дескрипторов, name/length, receiver, нативных ошибок и типа результата. Публичные классы и prototypes Temporal не заменяются. В отсутствие Temporal статус `absent` допустим; глобальный API и отсутствующие optional методы не создаются. Внутренний polyfill календарного движка остаётся приватным.

Неполный, несовместимый старый API Now.timeZone или запрещённые дескрипторы дают `unsupported`. В этом случае timezone Date/Intl также не подменяется. Публичный Temporal, который приложение загрузило после document_start, не охватывается. Форматирование и сериализация экземпляров публичных классов Temporal остаются нативными.

## Date между контекстами и в сериализации

Подкласс Date сохраняет instanceof, собственный prototype, NewTarget и внутренний timestamp при создании. JSON продолжает использовать исходный Date.prototype.toJSON/toISOString: UTC-строка, `null` для Invalid Date, пользовательский toJSON и JSON reviver сохраняют обычное поведение.

structuredClone не оборачивается. При его наличии проверяется сохранение timestamp и Invalid Date, а также Date.prototype принимающего realm. Нативный клон подкласса Date является обычным Date принимающего контекста; пользовательские методы и дополнительные поля подкласса в него не переносятся. Проверены общие ссылки, Map и циклы. Функции и Proxy не становятся клонируемыми. Отсутствующий structuredClone отмечается как `absent` и не создаётся.

При передаче живого Date между доступными realm его prototype остаётся исходным. Вызов `foreignDate.getHours()` использует метод чужого контекста; `Date.prototype.getHours.call(foreignDate)` — метод текущего. Timestamp общий. Контрольный контекст сохраняет свои нативные методы. Подмена не обходит Same Origin Policy, не получает закрытые cross-origin окна и не распространяется на workers.

Контракт опирается на нативную [сериализацию Date и восстановление в targetRealm](https://html.spec.whatwg.org/multipage/structured-data.html#structuredserializeinternal). Набор современных методов Now описан в [Temporal.Now](https://tc39.es/proposal-temporal/docs/now.html).

## Самопроверка и установка

`src/runtime/time.ts` объединяет CalendarEngine, Temporal, locale/timezone и Date. Исходные intrinsic захватываются до подмен. После установки `time-compatibility.ts` проверяет:

- Date/Intl зимой и летом, создание из компонентов, локальный setter, неизменность timestamp/UTC и явной зоны;
- ISO/JSON/Invalid Date и исходные абсолютные методы;
- имеющийся structuredClone и prototype результата;
- имеющийся Temporal.Now: пояс, значения локальных методов, сохранность instant и явной UTC.

При любой неуспешной проверке timezone-подмены Date, Intl и Temporal откатываются в обратном порядке. Затем отдельно устанавливается locale без подмены timezone. Ошибка отката требует перезагрузки и не выдаёт успешное покрытие.

В отчёте появились `temporal` и `timeCompatibility` с результатом, списком проверок и ошибок. `timeCoverage.complete=true` разрешён только при успешной установке всего заявленного набора. Temporal может быть `installed` либо явно `absent`; противоречивые значения, старый ACK и неуспешная проверка не дают INSTALLED/READY/commit. Signature реализации — 4; прежний документ требует reload.

`TIME_RUNTIME_COMPLETE=true` означает завершённость кода заявленных поверхностей I13–I18. Фактическая активация всё ещё требует полного успешного M0 для текущей версии Chrome, доступности API и lifecycle-подтверждений выбранных документов. Телеметрия MAIN остаётся недоверенной диагностикой, привязка документа берётся из native sender. Это не гарантия полной неотличимости окружения.

## Доказательства и оставшаяся приёмка

Добавлены 22 теста: 9 Temporal, 11 совместимости/стенда, 2 FrameRegistry. Всего 163. Проверки Date предыдущих шагов с нативным Node Date в отдельных TZ также входят в общий запуск.

В feature-present тестах Temporal предоставлен локальным `@js-temporal/polyfill 0.5.1` внутри VM; spies отдельно проверяют передачу зоны исходным Now-методам. Это тестовый заменитель API. Нативное клонирование между VM проверено сериализатором V8 через MessageChannel и `moveMessagePortToContext`; это не запуск browser structuredClone. Среда: Node 22.23.2, ICU 78.2, tz 2026a. Эти версии не приписываются Chrome.

Первый скрипт I02 теперь сохраняет снимки Temporal.Now, JSON/structuredClone Date и timeCompatibility. Значения nanoseconds экспортируются строками, ранние снимки заморожены. Для браузерной приёмки остаётся получить полный M0, затем сравнить первый снимок выбранных документов и контрольного сайта, явную UTC, обмен Date с доступными iframe, подклассы/clone и OFF/reload. При наличии Temporal проверяется native Now; отсутствие отмечается отдельно. Проверять также неподдержанный/заблокированный API и отсутствие ложного READY.

В I18 новой попытки управления Chrome не выполнялось. Из предыдущих шагов известна версия Chrome (номер версии удалён) и частичный снимок I02; установки dist/dist-probe и полного доказательства M0 нет. Ранее выданное разрешение на установку сохраняется. [История браузерной попытки](implementation-log.md).

Сохраняются ограничения [Date I16–I17](i16-i17-implementation.md): неизвестные строки дают NaN, исторический offset с секундами не представим без потерь в GMT±HHmm строке Date. Раскладка, хранилища, IP, workers и сложные lifecycle остаются за пределами I18. Новых зависимостей и permissions нет.
