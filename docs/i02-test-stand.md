# Стенд и приёмка I02

Код стенда готов. Полная проверка установленного расширения **не выполнена**, M0 остаётся неподтверждённой. Позднее, при I04–I10, получены версия Chrome (номер версии удалён) и частичный снимок пяти документов/25 запросов. Это не полный baseline без расширения. Computer Use затем остановил управление: текущий URL нельзя было надёжно определить. Доступность userScripts/DNR этим не установлена. Текущий [статус](i02-validation-status.json).

## Запуск

Из корня проекта, с Node.js 22 или новее:

```powershell
npm ci
npm run check
npm run fixture
```

Последняя команда оставляет сервер работающим в терминале. Остановка — `Ctrl+C`. Сервер слушает только `127.0.0.1`; файлы hosts и настройки ОС не меняются. При занятом порте сначала остановите прежний экземпляр стенда: диагностическая сборка рассчитана на фиксированные порты.

| Роль | HTTP-адрес | MAIN-маркер и тестовый заголовок при активной пробе |
| --- | --- | --- |
| Выбранный сайт | [selected.localhost](http://selected.localhost:8787/) | Да |
| Его выбранный поддомен | [app.selected.localhost](http://app.selected.localhost:8787/) | Да |
| Исключённый поддомен | [excluded.selected.localhost](http://excluded.selected.localhost:8787/) | Нет |
| Посторонний сайт | [control.localhost](http://control.localhost:8787/) | Нет |

Страница выводит два независимых источника: неизменяемый снимок **первого inline script** и данные **первого запроса документа, полученного сервером**. Поздняя установка маркера не меняет первый снимок. Отдельно показываются fetch-запросы ко всем четырём адресатам. Каждая основная страница содержит четыре iframe; `/frame` не создаёт вложенные iframe.

Обычные сайты не затрагиваются. Даже в диагностической сборке MAIN-код дополнительно проверяет точные origin, порт и путь. DNR ограничен двумя точными адресатами и портом стенда. Это фиксированная проверка возможностей; универсальный resolver политики сайтов реализован в I04 обычной сборки и не меняет фиксированную область диагностической пробы.

## Secure context и HTTPS

Для loopback-адресов `.localhost` предусмотрена проверка `window.isSecureContext` в самом первом скрипте. Положительный результат не предполагается заранее: `false` приводит к провалу приёмки. Спецификация допускает доверенный контекст для localhost при соответствующей локальной обработке имён: [W3C Secure Contexts](https://www.w3.org/TR/secure-contexts/#is-origin-trustworthy).

Если нужен именно HTTPS, сервер принимает ваши PEM-файлы сертификата и ключа:

```powershell
npm run fixture -- --cert "certs/localhost.pem" --key "certs/localhost-key.pem"
```

HTTP останется на 8787; HTTPS добавится на 8788. Сертификат должен быть действительным для всех четырёх имён и уже доверенным вашему Chrome. Стенд не устанавливает сертификаты и не отключает TLS-проверки. Папка `certs/` исключена из Git. HTTPS с действительным сертификатом в текущей среде не проверялся.

В диагностической странице выберите HTTPS **перед** подготовкой нового baseline. Для HTTPS исходный снимок без расширения также нужно снять с HTTPS-адресов. Протокол нельзя менять во время активной пробы.

## Исходный снимок без расширения

1. В чистом профиле Chrome до установки наших расширений откройте [selected.localhost с общим идентификатором запуска](http://selected.localhost:8787/?run=before-extension).
2. Дождитесь строки «Наблюдение записано на сервере» и загрузки четырёх iframe.
3. Из навигации страницы откройте три оставшихся основных сайта. Все ссылки сохраняют `run=before-extension`. На каждой дождитесь записи наблюдений.
4. Откройте [общий серверный JSON этого запуска](http://selected.localhost:8787/api/report?run=before-extension) и сохраните JSON-файл. В нём должны быть основные документы и iframe всех четырёх хостов, их fetch-запросы и `fullVersionList` Google Chrome.
5. Во всех снимках `marker` должен быть `null`, в серверных запросах `probeHeader` должен быть `null`. Сохраняются исходные language/languages, locale, timezone, timezoneOffset и Accept-Language; геолокационное разрешение не запрашивается.

Точная версия берётся из `navigator.userAgentData.getHighEntropyValues(["fullVersionList"])`, а не из сокращённого User-Agent: [Chrome User-Agent Client Hints](https://developer.chrome.com/docs/privacy-security/user-agent-client-hints). Если точная версия недоступна, результат остаётся INCOMPLETE. Синтетические версии в unit-тестах не являются наблюдениями браузера.

## Проверка установленного расширения

1. В `chrome://extensions` загрузите распакованную папку **`dist-probe`**. Это отдельное расширение «Региональный профиль — стенд I02». Проверьте отсутствие ошибок manifest и service worker. Обычную папку `dist` не заменяйте диагностической.
2. Нажмите значок диагностического расширения: откроется вкладка с проверками. На новой установке проба не зарегистрирована; проверить это можно в `session.inspections`: список `userScripts.registrations` и список `dnr.ruleIds` пусты.
3. В Chrome 138+ вручную выключите **Allow User Scripts / Разрешить пользовательские скрипты** в сведениях об этом расширении. Обновите диагностическую вкладку, выберите наблюдение «Выключен» и нажмите «Проверить API». Ошибка вызова `userScripts.getScripts()` должна отразиться как `available: false`, а не как успех.
4. Вручную включите этот переключатель, снова обновите диагностическую вкладку, выберите «Включён» и нажмите «Проверить API». Нужны успешные реальные вызовы userScripts и DNR и `hostAccess: true`. Для Chrome до 138 документация указывает Developer mode вместо отдельного переключателя; после его изменения также требуется заново открыть доступную страницу расширения. См. [Chrome userScripts](https://developer.chrome.com/docs/extensions/reference/api/userScripts#enable_usage_of_the_userscripts_api).
5. Нажмите «Подготовить baseline». Откройте все четыре ссылки **baseline**, дождитесь записи наблюдений и нажмите «Собрать отчёт». Должен получиться `evidence.baseline.status: PASS`: установка диагностической сборки без запуска пробы сохраняет исходное поведение.
6. Через поле исходного JSON выберите сохранённый ранее файл **без расширения**. Источник указан пользователем; это явно записывается в метаданных импорта. Код проверяет содержимое, восемь сочетаний хост/контекст и точную версию, но не может самостоятельно доказать отсутствие расширения в момент чужого сохранения.
7. Нажмите «Зарегистрировать пробу». Сначала регистрируется `userScripts` с `world: MAIN`, `runAt: document_start`, затем устанавливаются session rules DNR. Только после успешного завершения откройте четыре ссылки **armed**. Проверяются новые навигации; уже прочитанные значения не исправляются задним числом.
8. Нажмите «Собрать отчёт». Выбранный сайт и выбранный поддомен должны увидеть маркер текущего запуска уже в первом inline script; исключённый и контрольный сайты — `null`. Сервер должен получить на выбранных адресатах `X-Region-I02-Probe: <runId>` и `Accept-Language: en-XA,en;q=0.9` в первом запросе документа и fetch. Контрольные адресаты должны сохранить исходные заголовки, в том числе при запросе из выбранного документа.
9. Нажмите «Снять пробу», откройте четыре ссылки **off** и соберите отчёт. Нужны отсутствие маркера и тестового заголовка, возврат исходного Accept-Language и подтверждённое удаление собственных регистраций/правил.
10. Экспортируйте JSON. Время проверок, extension ID, полная версия Chrome, состояние API, наблюдение переключателя пользователем, серверные запросы и снимки страниц входят в отчёт.

Доступ DNR проверяется через `declarativeNetRequestWithHostAccess`, с разрешениями для всех четырёх инициаторов/адресатов стенда. Выбор сайтов не выводится из наличия permission: два контрольных хоста остаются контрольными. Основание: [Chrome declarativeNetRequest](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest).

## Оценка результата

`CONFIRMED` требует всех четырёх фаз: исходный импорт без расширения, baseline с установленной неактивной диагностикой, armed и off. Во всех фазах нужны документы и iframe четырёх хостов, отдельные серверные fetch-наблюдения и одна точная версия Google Chrome. Дополнительно нужны реальные вызовы API при выключенном/включённом переключателе, явное наблюдение пользователя о его положении и успешная очистка.

`NOT_RUN`, `INCOMPLETE`, `FAIL` и общий `NOT_CONFIRMED` не закрывают M0. Если MAIN/document_start или DNR недоступны, дальнейшие зависимые итерации I06/I07/I13 не начинаются до решения. Замена ранней проверки поздним `executeScript`, CDP или симуляцией не используется.

## Проверки кода

`npm run check` проверяет типы и обе сборки; обычная сборка по-прежнему ограничена разрешением storage. Тесты запускают настоящий HTTP-сервер на случайном loopback-порту и проверяют протокол, первый скрипт, echo, разделение хостов, iframe, привязку наблюдений и отсутствие cookies/authorization в отчёте. Отдельно проверяются фиксированные DNR-границы, отказ userScripts, откат после сбоя и оценка неполных/отрицательных доказательств.

Chrome API в unit-тестах заменяются тестовыми объектами; первый снимок в них выполняется в Node VM. Эти проверки подтверждают код стенда, а не возможности установленного расширения. Сервер хранит до 32 запусков в памяти; перезапуск сервера удаляет журнал, поэтому исходный JSON нужно сохранить до перезапуска. Переполнение журнала помечается `truncated` и не считается успешной проверкой.

## Дополнения стенда после I04–I10

Обычные страницы также загружают classic script с control.localhost: он читает API в realm загрузившего документа. Его запрос записывается в отдельный журнал resources. `/redirect?to=selected|subdomain|excluded|control&run=...` создаёт редиректы только к фиксированным адресатам стенда; они также не смешиваются с исходным протоколом M0. В первом снимке есть метаданные regionalRuntime, если он установлен.

Кнопки геолокации вызывают getCurrentPosition/watchPosition только по нажатию; clearWatch отменяет наблюдение. Доступны timeout/maximumAge/enableHighAccuracy. Координаты остаются в странице и не отправляются серверу. iframe получает `allow="geolocation"`, что не заменяет разрешение Chrome. Первый снимок также содержит числовые форматы, зиму/лето/DST, timestamp/UTC/local/offset и timeCoverage. Эти дополнения I11–I15 не подменяют обязательные фазы baseline/armed/off диагностической пробы.
