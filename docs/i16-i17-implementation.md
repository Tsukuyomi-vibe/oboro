## I16 — конструктор и парсинг

new Date(year, month, ...) интерпретирует компоненты в timezone профиля. Переполнение месяцев, дней, времени и миллисекунд нормализуется до преобразования в UTC; TimeClip применяется к конечному instant. Пропущенный аргумент использует нативный default, явный undefined преобразуется в NaN. Первые семь аргументов преобразуются слева направо; лишние не преобразуются.

Сохраняются new Date() с текущим временем, new Date(timestamp), копирование внутреннего значения другого Date (включая cross-realm), ToPrimitive/default для прочих объектов, subclass и NewTarget. Date() как функция продолжает возвращать локальную строку, игнорируя аргументы. Date.now и Date.UTC не изменены.

Для строк принята явная политика:

| Строка | Интерпретация |
| --- | --- |
| YYYY, YYYY-MM, YYYY-MM-DD | UTC |
| ISO date-time без offset | Timezone профиля |
| ISO date-time с Z или ±HH:mm | Указанный offset |
| Строка Date.toString с GMT±HHmm | Указанный offset |
| Строка Date.toUTCString | UTC |
| Остальные форматы | NaN / Invalid Date |

Поддержаны четырёхзначный год, expanded year ±шесть цифр, неполные ISO date-only формы, HH:mm / HH:mm:ss и 24:00 при нулевом остатке времени. Год -000000, неверные диапазоны и невалидные компоненты отвергаются. В пределах DD=01–31 короткие месяцы нормализуются как в V8: например 2024-02-30 → 1 марта.

Как явно проверенные расширения принимаются дробные секунды произвольной длины с усечением до миллисекунд и offset ±HHmm без двоеточия. Нижний регистр t/z, пробел вместо T, лишние внешние пробелы, timezone annotations и неоднозначные строки вроде 01/02/2024 не принимаются. Native Date.parse не вызывается как fallback, поэтому неизвестный формат не получает системную timezone.

Базовое различие date-only/date-time/offset соответствует [ECMA-262 Date.parse](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-date.parse). Эти правила используются одинаково Date.parse и строковым конструктором.

## I17 — локальные setters

Покрыты setDate, setFullYear, setHours, setMilliseconds, setMinutes, setMonth, setSeconds и существующий legacy setYear. UTC-setters и setTime сохранены без замены.

Каждый setter читает внутренний timestamp до преобразования аргументов. Если valueOf меняет этот же Date, пропущенные поля всё равно берутся из исходного снимка. Аргументы преобразуются и для Invalid Date. Невосстанавливающий setter на исходном NaN возвращает NaN без дополнительной записи: побочное изменение, сделанное valueOf, не теряется.

setFullYear и setYear восстанавливают Invalid Date от локального 1970-01-01 00:00, без предварительного сдвига эпохи в timezone профиля. setFullYear использует буквальный год; setYear и многокомпонентный конструктор сохраняют legacy правило 0–99 → 1900–1999. Исключение преобразования не делает дополнительную запись; NaN/Infinity при допустимом вызове дают Invalid Date.

Результат всегда записывается нативным setTime в исходный объект; возвращается конечный timestamp. Проверены receiver, Date другого realm, frozen Date, subclass, name/length/дескрипторы и игнорирование лишних аргументов.

## Календарь и границы

Конструктор, локальный parser и setters используют один CalendarEngine и disambiguation compatible: первый instant при overlap и сдвиг вперёд при gap. setDate на сутки через DST может изменить timestamp на 23/25 часов. Даже setter с тем же локальным значением во втором повторённом часу может перейти к первому instant — это нативная семантика Date.

Балансировка компонентов использует захваченный Date.UTC; 400-летний григорианский цикл исключает его отдельное правило годов 0–99 при работе с буквальным годом. При clipping до учёта offset вычисляется wall time, а дополнительная проверка native MakeDay сохраняет отказ на экстремальных входах V8. Это также покрыто тестами.

У границ ±8.64e15 локальные поля могут выходить за диапазон Instant, хотя результирующий timestamp допустим. Для случаев, отвергаемых Temporal-компонентом, engine разрешает offset на доступной стороне границы по тем же IANA-данным. Дополнительной timezone-базы или локального календарного сервиса нет.

Исправлена совместимость I15: Date.getTimezoneOffset возвращает целые минуты, как наблюдаемый V8; CalendarEngine сохраняет точные исторические offset nanoseconds для преобразований. Например, Paris 1900 имеет локальные секунды :21 и API offset -9 минут. Строковый GMT±HHmm не несёт исторические секунды offset: round trip через такую строку не гарантирует исходный instant. ISO/toISOString и toUTCString сохраняют абсолютное время.

Компонент остаётся @js-temporal/polyfill 0.5.1 с локальным bundle; правила IANA берутся из Intl/ICU. Самопроверка дополнена нормализацией Date-компонентов и выполняется до установки.

## Интеграция и покрытие

Date-модуль устанавливается атомарно: getters, строки, constructor, parser и setters подготавливаются вместе; ошибка неизменяемого descriptor не выдаётся за успешную установку. Implementation signature повышена до 3: существующему документу нужен reload. Старый ACK с false construction/parse/localSetters не подтверждает новое покрытие.

В timeCoverage теперь true: formatting, localRead, construction, parse, localSetters. Temporal и complete остаются false. Состояние успешного применения — LIMITED с причиной незавершённого I18 и ограниченного строкового parser. UI описывает фактическую поддержку. Новых permissions нет; M0 gate и область выбранных сайтов сохранены.

Первый скрипт стенда фиксирует Date-компоненты, локальный/date-only/явный UTC parser, отказ неоднозначной строки и результаты setDate/setMonth/setHours. Значения заморожены, не запрашивают геолокацию и дополняют текущий протокол I02.
