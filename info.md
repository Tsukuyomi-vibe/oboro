# oboro — вся информация, которую подменяет приложение

Версия: **0.0.1**. Описание обновлено по текущему коду 28 ноября 2026 года.

Документ описывает подмену данных, доступных сайту через JavaScript и HTTP-заголовки. Одна настройка может влиять на несколько API: например, выбранный часовой пояс определяет и локальные часы, и смещение UTC, и форматирование дат.

Язык интерфейса oboro (English по умолчанию или Русский) — отдельная локальная настройка `oboro.language`. Она сохраняется при изменении, не относится к подмене данных сайта и не меняет `navigator.language`, `navigator.languages`, Accept-Language или локаль регионального профиля.

Исправление конфиденциальности от 23 ноября: диагностические сообщения страницы не содержат список разрешённых сайтов, название профиля, общий идентификатор применения или номера редакций. Используется отдельное подтверждение для каждого документа. Для удаления старого диагностического объекта после обновления нужна перезагрузка ранее обработанных страниц. [Подробности](docs/privacy.md).

## 1. Все настраиваемые параметры

В профиле **6 параметров подмены**: широта, долгота, список языков, локаль форматов, часовой пояс и карта раскладки.

| Параметр | Поле профиля | Допустимое значение / смысл |
| --- | --- | --- |
| Широта | `geolocation.latitude` | Конечное число от −90 до 90 градусов включительно |
| Долгота | `geolocation.longitude` | Конечное число от −180 до 180 градусов включительно |
| Предпочитаемые языки | `languages` | От 1 до 10 корректных языковых тегов в порядке предпочтения, без повторов после нормализации |
| Локаль форматов | `locale` | Поддерживаемый языковой тег, например `de-DE`, `en-US`, `ru-RU` |
| Часовой пояс | `timeZone` | Поддерживаемый именованный идентификатор, например `Europe/Berlin`, `Asia/Tokyo`, `UTC` |
| Карта раскладки | `keyboardLayout` | Системная карта либо фиксированная US QWERTY, DE QWERTZ или RU ЙЦУКЕН |

**Обязательно только поле «Название»** — от 1 до 80 символов после удаления пробелов по краям. Оно обозначает профиль в интерфейсе и не подменяет параметр браузера, доступный сайту. Все 6 параметров подмены независимы и необязательны. Пустой инпут означает «значение текущего браузера»; системная карта раскладки имеет тот же смысл. Версия схемы и номера редакций профиля и правил являются служебными данными.

В форме поддерживается десятичная запятая. Пустые поля не записываются как подмены; числовой ноль остаётся заданным значением. В геолокации доступны только широта и долгота. Точность, высота, точность высоты, скорость и направление всегда сохраняются из каждого ответа браузера; для них больше нет инпутов или настроек.

Экспорт использует `oboro-config` со схемой 1 и обязательной версией экспортирующего приложения. Например, профиль `123` с одной широтой содержит `geolocation: { "latitude": 52.52 }`; долгота, языки, локаль, пояс и карта принимающего ПК не записываются в качестве значений по умолчанию. Исторические полные файлы v1 и файлы v2 читаются с удалением пяти упразднённых геонастроек; предпросмотр поясняет это изменение. Новый v1 из oboro 0.0.1 эти поля не принимает. Предыдущие файлы v3 также поддерживаются. Служебная схема профиля в локальном хранилище остаётся 3 и независима от версии переносимого JSON. [Контракт конфигурации](docs/configuration-format.md).

## 2. Геолокация

Подменяются данные, которые сайт получает через:

```js
navigator.geolocation.getCurrentPosition(position => {
  console.log(position.coords);
});

const watchId = navigator.geolocation.watchPosition(position => {
  console.log(position.coords);
});
```

| Информация, которую получает сайт | Способ чтения |
| --- | --- |
| Широта профиля | `position.coords.latitude` |
| Долгота профиля | `position.coords.longitude` |
| Те же значения при сериализации | `position.toJSON()`, `position.coords.toJSON()` |

Особенности:

- Если геополя не заданы, методы геолокации остаются нативными. При частичной подмене get/watch получают реальный ответ браузера и заменяют только заданные поля. Остальные могут меняться при последующих наблюдениях.
- Расширение не создаёт фиксированную синтетическую позицию, маршрут или таймер движения. Наблюдение останавливается через `clearWatch(watchId)`.
- `position.timestamp` всегда сохраняется из нативного ответа. Отдельной настройки для него нет.
- Опции `maximumAge`, `timeout`, `enableHighAccuracy`, разрешения и ошибки обрабатывает нативный API. Если позиция недоступна, возвращается его ошибка; дополнительные координаты не выдумываются.
- Доступность API, безопасный контекст и разрешения браузера сохраняют значение. Расширение не делает `navigator.permissions.query({ name: 'geolocation' })` фиктивно разрешённым и не отменяет запрет Permissions Policy.
- Диалог разрешения открывается нативным API. Только заданные широта и долгота заменяются; все остальные значения передаются из нативного результата.
- При уходе страницы геонаблюдения очищаются. После возврата из BFCache для их возобновления может понадобиться перезагрузка.

## 3. Языки браузера и HTTP-запросов

Один список `languages` определяет три представления языка:

Если список не задан, все три представления остаются исходными, сетевые правила Accept-Language не создаются.

| Подменяемая информация | Как сайт получает значение | Как формируется |
| --- | --- | --- |
| Основной язык браузера | `navigator.language` | Первый язык списка |
| Список предпочитаемых языков | `navigator.languages` | Весь список с сохранением порядка |
| Предпочитаемые языки HTTP-запроса | Заголовок `Accept-Language`, который читает сервер | Первый язык без веса; последующим назначаются веса `q=0.9`, `q=0.8` и далее до `q=0.1` |

Пример для списка `de-DE, de, en-US`:

```text
navigator.language: de-DE
navigator.languages: ["de-DE", "de", "en-US"]
Accept-Language: de-DE,de;q=0.9,en-US;q=0.8
```

Языковые теги нормализуются через `Intl`. Список языков и локаль форматов задаются независимо: язык `navigator.language` сам по себе не выбирает `locale`.

Подмена `Accept-Language` относится к адресу получателя запроса и зависит от правил сайтов и разрешений Chrome. Подмена JavaScript API относится к документу страницы. Запрос выбранной страницы к постороннему получателю не получает язык профиля автоматически.

Другие HTTP-заголовки, в том числе `User-Agent` и Client Hints, основная сборка не подменяет. Отдельная диагностическая сборка использует тестовые заголовки для проверки совместимости; это не дополнительная настройка регионального профиля.

## 4. Региональная локаль и форматы

Подменяется локаль по умолчанию. Она влияет на результаты следующих существующих в браузере API.

| API / способ чтения | На какую информацию влияет локаль |
| --- | --- |
| `new Intl.DateTimeFormat().resolvedOptions().locale` | Локаль форматирования дат |
| `new Intl.NumberFormat().resolvedOptions().locale` | Локаль форматирования чисел |
| `new Intl.DateTimeFormat().format(date)` и `formatToParts(date)` | Порядок частей даты, названия месяцев и дней, разделители и другие региональные правила форматирования |
| `new Intl.NumberFormat().format(1234567.89)` и `formatToParts(1234567.89)` | Десятичный разделитель, группировка разрядов, система цифр и правила форматирования согласно локали и опциям сайта |
| `(1234.5).toLocaleString()` | Локализованная строка числа |
| `(1234n).toLocaleString()` | Локализованная строка BigInt |
| `date.toLocaleString()` | Локализованная дата и время |
| `date.toLocaleDateString()` | Локализованная дата |
| `date.toLocaleTimeString()` | Локализованное время |
| `new Intl.Collator().compare(a, b)` | Правила сравнения и сортировки строк |
| `a.localeCompare(b)` | Локализованное сравнение строк |
| `text.toLocaleLowerCase()` | Правила перевода строки в нижний регистр |
| `text.toLocaleUpperCase()` | Правила перевода строки в верхний регистр |
| `new Intl.PluralRules().select(number)` | Категория множественного числа |
| `new Intl.RelativeTimeFormat().format(-1, 'day')` | Представление относительного времени |
| `new Intl.ListFormat().format(['A', 'B'])` | Представление списков и соединительных слов |
| `new Intl.DisplayNames(undefined, { type: 'region' }).of('DE')` | Локализованные названия регионов; аналогично — других поддерживаемых типов названий |
| `new Intl.Segmenter().segment(text)` | Зависящие от локали правила сегментации текста |
| `new Intl.DurationFormat().format({ hours: 2 })` | Представление длительности, если API доступен |

Подмена затрагивает создание перечисленных объектов `Intl`; их методы используют выбранные при создании параметры. Зависимые значения, например календарь, система цифр или часовой цикл, могут отражать локаль и опции, возвращаемые `resolvedOptions()`. Отдельных полей для каждого такого результата в форме нет.

Ограничения:

- Если сайт явно передал непустой список локалей, его выбор сохраняется. Профиль подставляется при отсутствии локали, `undefined` или пустом списке.
- Числовые значения не меняются: меняется их представление в строках.
- Валюта не выбирается отдельной настройкой. Если сайт запросил валютное форматирование, локаль определяет его региональное представление, а валюта остаётся заданной сайтом.
- Содержимое сайта не переводится автоматически. Сайт сам решает, использовать ли язык браузера или сетевой заголовок.
- Отсутствующие в браузере API не создаются. Например, отсутствие `Intl.DurationFormat` сохраняется.

## 5. Часовой пояс и локальное представление времени

Если часовой пояс задан, подменяется зона по умолчанию. Из неё вычисляются локальная дата, местное время, день недели и смещение относительно UTC с учётом переходов на летнее время. Пустой пояс сохраняет исходную зону браузера. Пустая локаль сохраняет его форматирование даже при заданном поясе; одна локаль без пояса не меняет Date-конструктор, локальные часы или Temporal.Now.

### 5.1. Чтение через Date и Intl

| Подменяемая информация / поведение | Способ получения сайтом |
| --- | --- |
| Идентификатор часового пояса по умолчанию | `new Intl.DateTimeFormat().resolvedOptions().timeZone` |
| Локальный год | `date.getFullYear()`, устаревший `date.getYear()` |
| Локальный месяц | `date.getMonth()` |
| Локальный день месяца | `date.getDate()` |
| Локальный день недели | `date.getDay()` |
| Локальные часы | `date.getHours()` |
| Локальные минуты | `date.getMinutes()` |
| Локальные секунды | `date.getSeconds()` |
| Миллисекунды локального представления | `date.getMilliseconds()` |
| Смещение относительно UTC, минуты в соглашении JavaScript | `date.getTimezoneOffset()` |
| Строка локальной даты и времени с GMT-смещением и названием зоны | `date.toString()`, `String(date)` |
| Строка локальной даты | `date.toDateString()` |
| Строка локального времени с GMT-смещением и названием зоны | `date.toTimeString()` |
| Строка текущей локальной даты и времени | Вызов `Date()` как функции |
| Локализованная дата и время в зоне профиля | `date.toLocaleString()`, `date.toLocaleDateString()`, `date.toLocaleTimeString()` |
| Форматирование даты в зоне профиля | `new Intl.DateTimeFormat().format(date)` и другие методы созданного форматтера |

Для этих методов не создаётся отдельная настройка времени: один и тот же момент времени отображается в выбранной зоне. Миллисекунды также входят в пересчёт локальных полей, хотя обычное изменение пояса их не меняет.

### 5.2. Создание, разбор и изменение локальных дат

Подмена влияет также на результат операций, где сайт задаёт локальное время без явного часового пояса:

| Операция | Поведение |
| --- | --- |
| `new Date(year, month, day, hours, minutes, seconds, milliseconds)` | Компоненты интерпретируются в зоне профиля |
| `new Date('2024-01-15T12:00')` | ISO дата-время без зоны интерпретируется в зоне профиля |
| `Date.parse('2024-01-15T12:00')` | Аналогичный разбор локального времени в зоне профиля |
| `date.setDate()` | Изменение локального дня месяца в зоне профиля |
| `date.setFullYear()` | Изменение локального года и переданных дополнительных компонентов |
| `date.setMonth()` | Изменение локального месяца и переданного дня |
| `date.setHours()` | Изменение локального времени и переданных дополнительных компонентов |
| `date.setMinutes()` | Изменение локальных минут и переданных секунд/миллисекунд |
| `date.setSeconds()` | Изменение локальных секунд и переданных миллисекунд |
| `date.setMilliseconds()` | Изменение локальных миллисекунд |
| `date.setYear()` | Поддерживаемое браузером устаревшее изменение локального года |

Переходы летнего времени, неоднозначное и несуществующее локальное время обрабатываются общим календарным движком. Неоднозначные нестандартные строки вроде `01/02/2024` отвергаются с `Invalid Date` / `NaN`; системный часовой пояс не используется как запасной способ разбора.

### 5.3. Temporal.Now, если API уже существует

| Подменяемая информация | Способ получения сайтом |
| --- | --- |
| Часовой пояс по умолчанию | `Temporal.Now.timeZoneId()` |
| Текущие дата и время с зоной | `Temporal.Now.zonedDateTimeISO()` |
| Текущие локальные дата и время | `Temporal.Now.plainDateTimeISO()` |
| Текущая локальная дата | `Temporal.Now.plainDateISO()` |
| Текущее локальное время | `Temporal.Now.plainTimeISO()` |

Если в поддерживаемой реализации уже присутствуют дополнительные методы `Temporal.Now.zonedDateTime`, `plainDateTime`, `plainDate` или `plainTime`, их отсутствующий аргумент зоны также заменяется зоной профиля с сохранением остальных аргументов.

Подмена применяется к совместимому `Temporal`, доступному в начале загрузки документа. Расширение не добавляет публичный `Temporal` на сайт и не подменяет полифилл, загруженный сайтом позднее.

### 5.4. Что сохраняется при подмене времени

- Абсолютное время: `Date.now()`, `date.getTime()`, `date.valueOf()` и момент времени, получаемый через `new Date()` без аргументов.
- `Date.UTC()`, UTC-getters, UTC-setters, `setTime()`, `toUTCString()` и `toGMTString()`.
- `date.toISOString()`, `date.toJSON()` и временные значения при JSON-сериализации и нативном клонировании Date.
- `performance.now()` и системные часы.
- `Temporal.Now.instant()`, его точность, конструкторы и прототипы объектов Temporal.
- Явно заданные сайтом часовые пояса в форматировании и поддерживаемых вызовах Temporal.
- Явные `Z` и числовые смещения в строках дат. ISO строка только с датой, например `2024-01-15`, сохраняет UTC-семантику.

Исторические смещения с точностью до секунд имеют ограничение представления в строках `Date` с суффиксом `GMT±HHmm`.

## 6. Карта раскладки клавиатуры

| Значение настройки | Что получает сайт |
| --- | --- |
| `native` — системная карта | Нативный результат; подмена карты не запрошена |
| `us-qwerty` — US QWERTY | Фиксированные подписи клавиш английской раскладки |
| `de-qwertz` — DE QWERTZ | Фиксированные подписи клавиш немецкой раскладки |
| `ru-jcuken` — RU ЙЦУКЕН | Фиксированные подписи клавиш русской раскладки |

Фиксированные карты содержат 49 клавиш основной текстовой области Windows PC без модификаторов, включая пробел и `IntlBackslash`.

Сайт получает карту так:

```js
const map = await navigator.keyboard.getLayoutMap();
console.log(map.get('KeyY'));
console.log([...map]);
```

Подменённые подписи доступны через `get()`, `has()`, `size`, `entries()`, `keys()`, `values()`, `forEach()` и стандартный итератор карты. Например, для физического кода `KeyY` карта US возвращает `y`, а карта DE — `z`.

При фиксированной карте подавляются доверенные системные события `layoutchange`, поскольку виртуальная карта документа остаётся постоянной. События, искусственно созданные самим сайтом, сохраняются.

Ограничения:

- Не изменяются вводимый текст, физическая раскладка ОС, `KeyboardEvent.key`, `KeyboardEvent.code`, сочетания клавиш, IME, `keyboard.lock()` и `keyboard.unlock()`.
- Сохраняются нативные ошибки доступа, фокуса и неправильного вызова API. Учитываются безопасный контекст и Permissions Policy `keyboard-map`.
- Если Keyboard Map API отсутствует, расширение не создаёт его.
- Выбор новой карты требует применения профиля и перезагрузки обработанных страниц.

## 7. Где и когда действует подмена

- JavaScript-подмена устанавливается в основном контексте страницы — MAIN — в начале загрузки документа, до обычных скриптов сайта. Если ранний момент пропущен, документу требуется перезагрузка.
- Обрабатываются выбранные HTTP/HTTPS-сайты с выданными Chrome-разрешениями. В режиме «Все сайты с уже выданным доступом» используются соответствующие выданные доступы. Исключения имеют приоритет.
- Iframe рассматривается по собственному адресу. Права и правила родительской страницы сами по себе не означают, что любой вложенный документ покрыт.
- Сетевой `Accept-Language` применяется по адресу получателя запроса и в пределах возможностей и разрешений Chrome.
- Применяется один активный профиль. Изменение сохранённого профиля не меняет задним числом уже прочитанные сайтом значения.
- При возврате документа из BFCache в нём могут оставаться прежние обёртки и версия профиля. Для применения новой версии требуется перезагрузка.
- Выключение снимает будущие регистрации и сетевые правила. Для возврата исходных API в уже обработанных документах нужна перезагрузка.
- Dedicated Workers, Shared Workers и Service Workers сайта не получают базовую подмену.
- Документы `about:blank`, `srcdoc`, `blob`, непрозрачные sandbox-контексты и контексты без подтверждённого HTTP/HTTPS-origin пропускаются.

## 8. Что приложение не подменяет

Следующие данные не входят в текущую региональную подмену:

| Данные / поверхность | Состояние |
| --- | --- |
| Публичный IP-адрес и сетевой маршрут | Не изменяются; расширение не является VPN или прокси |
| DNS, WebRTC и ICE-адреса | Специальная подмена или блокировка не реализована |
| User-Agent и User-Agent Client Hints | Не подменяются; могут считываться для диагностики Chrome |
| ОС, платформа, производитель браузера | Отдельная подмена не реализована |
| Canvas, WebGL, GPU и AudioContext | Подмена отпечатков не реализована |
| Размер экрана, разрешение, глубина цвета, devicePixelRatio | Не подменяются |
| Число процессорных ядер, память, шрифты и прочие аппаратные признаки | Не подменяются |
| Cookies, localStorage и IndexedDB сайтов | Подмена или очистка данных сайтов не реализована |
| Регион и язык учётной записи на сервере сайта | Не изменяются |
| Реальный ввод с клавиатуры и IME | Остаются системными |
| Разрешения и системные диалоги Chrome | Не фальсифицируются |
| Точность координат, высота, точность высоты, скорость и направление | Сохраняются из каждого ответа браузера, включая null; настройки удалены |\n| Абсолютные часы и timestamp | Не сдвигаются настройкой часового пояса |
| API в workers сайта и поздние полифиллы | Не входят в базовое покрытие |

Тема интерфейса oboro — системная, светлая или тёмная — относится к оформлению расширения и Oboro Check. Она не подменяет тему сайта или результат `matchMedia('(prefers-color-scheme: dark)')` на сторонних страницах.

## 9. Условия подтверждения работы

Перечень выше описывает реализованное поведение версии 0.0.1. Для включения подмен текущая сборка требует полного отчёта совместимости для точной версии Chrome и доступности нужных API.

Модуль времени дополнительно проверяет согласованность Date, Intl, доступного Temporal.Now и нативного клонирования. При ошибке установки изменения часового пояса откатываются; форматирование с локалью профиля может остаться доступным отдельно. Отсутствие или неподдерживаемая версия API показываются в диагностике.

Полная приёмка установленного Chrome Stable/Beta ещё не завершена. Совпадение отдельных значений с профилем не доказывает покрытие всех способов получения информации сайтом.
